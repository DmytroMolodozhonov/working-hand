## Быстрая загрузка (кеш между запусками; просьба автора: «максимум выжать, но НЕ СЛОМАТЬ ИГРУ»)
- **Замер этапов:** `src/core/BootTimer.js` (`bootTimer` — общий для `main.js` и `Game`): строка «⏱ загрузка …: звуки X · мир Y · …» в журнал при каждом входе, таблица — `window.__zns.boot`; `node tools/entrybench.mjs [--profile-dir DIR] [--menu-wait 4] [--no-cache]` печатает «ЭТАПЫ» (с `--profile-dir` профиль браузера живёт между запусками: первый прогон — холодный, второй — тёплый, как у автора). Новый долгий шаг загрузки — сразу свой `B.span/begin/end`.
- **Кеш на диске** (`src/core/BootCache.js`): только дорогое и полностью заданное своими входами — синтезированные звуки (`SoundManager._readSoundCache/_writeSoundCache`, одна запись на частоту звука), картинки вещей (`ItemIcons._readKept/_writeKept`, ключ — видеокарта), тело и одежда «Детальной» модели (`RealisticBody.askKept`). НИКОГДА — земля, сохранения, сеть, состояние мира. Хранилище — Cache Storage профиля браузера игры (постоянный `--user-data-dir` лаунчера, `zns_browser.py`); у каждой записи — версия кода СВОЕГО вида (`server.py KIND_ROOTS/kind_builds()`: хеш содержимого всех файлов, до которых доходят импорты от корней вида — звуки 17 файлов, тело героя 7, иконки 95; вид без строки — вся сборка `build_id()`), так что обновление игры стирает только тот вид, чей код изменился (автор обновляется много раз в день — раньше каждое обновление стирало всё и разницы не было видно); старая версия записи удаляется при записи новой. Новый вид — строка в `KIND_ROOTS` с модулями, которые делают результат (остальное найдут импорты). Запись: магия, `FORMAT`, вид и ключ, контрольная сумма (`sum32`), одна запись целиком (закрыли игру посреди записи — записи нет); битая/чужая — удаляется и делается заново; запись не удалась (диск полный, только чтение) — дальше этот запуск без записи; предел 500 МБ, старые уходят (`trim`). Выключить: Настройки → Графика «Быстрая загрузка (кеш)», «Очистить кеш», `?nocache` / лаунчер `--no-cache` / `ZNS_NO_CACHE=1`. Журнал: «⚡ Кеш: звуки N из кеша / M заново …». Новый вид данных — в `BOOT.KINDS` и в `tools/bootcheck.mjs` (с кешем = без кеша), тест `tests/unit/boot-cache.test.js`.
- **Параллельно:** в меню (через ~0,6 с, в простое) уже читаются и раскодируются файлы звуков (музыка молчит до игры — `SoundManager.holdMusic`) и запускаются воркеры земли (`TerrainView.prespawnTerrainWorkers`: грузят генератор, ждут `init`); после «Начать» камера и её нейросети стартуют сразу (не после мира), синтез/чтение звуков идёт вместе с прорисовкой земли (`warmAll` — одна работа, второй вызов ждёт первый).
- **Найдено стендом `bootcheck`:** у звука может быть своя частота (тема Дьяволоса — половина частоты карты, `houseBreak` — 24 кГц): в записи у каждого звука своя `sr`; кешируются только звуки, синтезированные в главном потоке (`SoundManager._synthed`), не музыка заклинаний и тем из воркеров. Случайные по природе (88 из 158 звуков, текстуры меча и топора) с кешем просто не меняются от запуска к запуску. Кеш живёт у «сайта» `localhost:<порт>` — другой порт = пустой кеш (стенды с `--profile-dir` держат порт постоянным).
- **Замер (контейнер, программная видеокарта; `entrybench --profile-dir`, меню 4 с):** до кеша от «Начать» до начала прогрева шейдеров 38–43 с; теперь холодный 30 с, тёплый 13 с (звуки 12,6 → 1,4; иконки 8,5 → 1,6; файлы звуков 2–4,5 → 0 — уже в меню); шейдеры 67–75 с здесь не кешируются (программная карта), на настоящей видеокарте их держит кеш браузера.
- **Шейдеры:** их кеширует сам браузер на диске (GPUCache/GPUPersistentCache профиля игры) — профиль постоянный, флагов, выключающих кеш, нет; браузер ищет готовую программу по её тексту (порядок прогрева не важен). three r128 без `compileAsync` — параллельной компиляции нет (патч библиотеки — риск, не делали).
