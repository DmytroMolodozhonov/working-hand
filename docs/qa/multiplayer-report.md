# Тестирование мультиплеера и голоса (29.10.2026)

Задача автора: «глубокая система тестирования игры в МУЛЬТИПЛЕЕРЕ — дуэльного и обычного взаимодействия… как ТУПОЙ
ПОЛЬЗОВАТЕЛЬ… особое внимание — ГОЛОСУ: голосовое общение игроков через Discord, а не через игру». Потом — сразу чинить.

## Как проверяли (методики игрового QA)

| Методика | Что сделано |
|---|---|
| Матрица «кто × что × когда» | хост / гость / поздний гость / зритель × действие (дуэль, арена, торговля, вещи, оружие, держимые заклинания, Империус, дракон, пентаграммы, вихри) × состояние (идёт бой, игрок вышел, закрыл окно, умер, хост ушёл, пришёл посреди) — три независимых разбора кода по подсистемам, каждая находка проверена по строкам кода вручную |
| Граничные значения | размер сообщений сети (16 КБ предел канала PeerJS), 10 игроков, пустые/полные руки и ячейки, 30 000 правок мира |
| Фазз протокола | e2e `tests/e2e/multiplayer-qa.test.mjs`: каждый из ~230 типов сообщений `NetSync` — пустой, с полями не того типа, с абсурдными числами, с чужими id, дважды (дубль) и в обратном порядке; хост и второй гость не должны падать, никого не выкидывает |
| Статический аудит протокола | `tests/unit/net-protocol.test.js`: нет двух методов с одним именем, нет двух обработчиков одного типа, у каждого отправляемого сообщения есть получатель |
| «Тупой пользователь» | закрыл окно без «до свидания» (обрыв), хост закрыл игру, вышел с мечом в руке, умер посреди дуэли / сидит на экране смерти, стал невидимым на арене, продал вещь, которую уже забрали, Gather одновременно с другим |
| Голос + Discord | разбор всего пути фразы (`voice_native.py` → `NativeVoice.lookAt` → `SpellSpotter.hear` (эхо по колонкам) → `main.js` → `VoiceGate`); симуляция времени (задержка Discord, сеть, оба распознавателя) — `tests/unit/voice-discord-duel.test.js`; новая сцена стенда `voicebench` — `duel`; `npm run test:voice` на настоящих записях |
| Soak / нагрузка | у гостя список правок мира рос без предела и копировался целиком на каждое сообщение (найдено чтением, исправлено) |

## Голос и Discord — подробно

Путь звука: друг говорит → Discord (0,1–0,5 с) → мои колонки → мой микрофон. Защиты:

1. **Windows, программа голоса с шумоподавлением (`aec`)**: звук колонок вычитается из микрофона; заклинание, которое
   слышно и в колонках в то же время, считается эхом (`SpellSpotter`, `ECHO_AFTER` −0,08…0,45 с). Это самая надёжная защита.
   Её замер — стенд `tools/voicebench` (по README: «chat» 11/12, «overlap» 12/20, ложных от речи друга 0).
   Новая сцена **`duel`** (друг отвечает тем же заклинанием за ≤1 с до/после моего) добавлена — **запустить её здесь
   нельзя** (нет голосовых моделей и голосов Piper в облаке); порог в `floor.json` поставить после первого замера на
   компьютере автора: `tools/voicebench/run.sh /tmp/vb --n 20`. Ожидаемое слабое место: моё заклинание, начатое через
   0–0,45 с после такого же у друга, отсеется как эхо.
2. **Без шумоподавления (Mac, распознавание браузера)**: только губы (камера) и сетевое «друг сказал X». Исправлено V-01/V-02.
3. Что **не исправить кодом**: друг в Discord говорит заклинание, а его игра не запущена/голос в ней выключен — сообщения
   «он сказал» нет; без шумоподавления и без камеры на губах у меня оно может сработать. Совет игрокам — наушники
   (тогда эха нет вовсе) или программа голоса с шумоподавлением.

Измерено (`tests/unit/voice-discord-duel.test.js`, 600 дуэльных обменов, лицо не видно):

| | эхо друга сработало | мои ответы потеряны |
|---|---|---|
| было | 0 | 523 (87 %) |
| стало | 0 | 177 (29,5 %) — только начатые в пределах 1,3 с от начала его фразы |

`npm run test:voice` (настоящие записи) — без изменений: 36 из 36.

## Что проверено и работает правильно

- Двое хватают одну вещь/яблоко/мясо одновременно — второй ничего не получает (хост решает), повторный `igone` не даёт копию.
- Двойная оплата (`tpay` дважды) — второй раз нечем платить.
- Империус: контролёр или цель ушли — существо освобождается, игрок сам освобождается через 2,5 с без сигнала.
- Левиоса: держащий ушёл — падаю; потерянное «стоп» не оставляет висеть в воздухе.
- Ожившие деревья гостя: хозяин ушёл/умер — дерево перестаёт жить.
- Наездник дракона ушёл — дракон отпущен.
- Друг ушёл посреди отсчёта/боя на арене — бой отменён, место освобождено, зритель становится соперником.
- Хост ушёл — гостям сообщается, игра возвращается в меню.
- Повторные нажатия «Войти» — один игрок, не клоны (уже было покрыто тестами).

## Осталось (крупное или не моё)

| № | Что | Почему не сделано |
|---|---|---|
| R-01 | Два игрока одновременно делают Gather на один меч (в пределах задержки сети) — меч может оказаться у обоих | нужен новый запрос «можно взять?» к хосту с ответом; редкий случай (одновременность до 0,1 с) — отдельная задача |
| R-02 | Монеты двух игроков на одном прилавке складываются в одну оплату | нужно переделать оплату по кошелькам владельцев (`CastleTalk.pay`) |
| R-03 | Быстрый перезаход (старое соединение ещё живо) — новый вход без своих вещей на эту сессию (сохранение не портится) | нужно закрывать старое соединение того же игрока при входе |
| R-04 | Поздний гость посреди дуэли на арене не видит летящие заряды и сцепку (фазу видит со следующей смены) | нужно добавить заряды арены в «мир для нового игрока» |
| R-05 | Сцена `duel` в `voicebench` — не замерена | нужны голосовые модели (компьютер автора) |
| R-07 | Залп из сотен сломанных сообщений подряд (фазз в e2e, `ZNS_QA_FUZZ=1`) однажды подвесил страницу второго гостя в облачном браузере | по одному каждое сообщение проходит чисто (`tools/netfuzz.mjs`, обе роли, с «настоящим» соседом); в облаке графика программная (~1 кадр/с) — воспроизвести на обычном компьютере |
| R-06 | Хост ушёл — у гостя прогресс этой сессии остаётся только в сохранении хоста | так устроено (мир хранит хост) |

## Особенности облачного стенда (не ошибки игры)

- Два 3D-мира в одном безголовом браузере роняют его графику — в e2e у каждого игрока свой браузер (как разные компьютеры).
  Старый `tests/e2e/multiplayer.test.mjs` использует один браузер на всех и поэтому здесь не проходит (на компьютере автора — проверить).
- Игра в облаке рисуется программно (~1 кадр/с), мир стартует 25–60 с — таймауты e2e увеличены.
