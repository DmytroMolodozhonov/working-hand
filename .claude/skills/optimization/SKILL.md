# Оптимизация — кидать в промпт КАЖДОЙ сессии, где пишется код (сверяй с CLAUDE.md: «Всё сложное — на видеокарту», «Производительность»)

Принцип автора: «FPS не должен проседать», «всё сложное — на видеокарту, даже если только кажется, что сложно». Код сразу пишется не «браузерным», а под видеокарту.

1. **Тяжёлое — на видеокарту:** нейросети и расчёты — llama.cpp Vulkan/Metal (`llm_native.py`, `-ngl 99`), ONNX в браузере — WebGPU (`src/audio/tts.worker.js`), в Python на Windows — DirectML. Процессор — только запасной путь, причина — в журнал. Картинки при загрузке (цикл по пикселям, `getImageData` с холста) — шейдером в render target через `src/core/GpuTexture.js` (`bakeRenderer`/`runPasses`, запасной путь на процессоре), страж `tests/e2e/gpu-textures.test.mjs`; генерация мира, свет и меш чанков — в воркерах, не на видеокарте (почему — CLAUDE.md, замер `node tools/loadbench.mjs`).
2. **Ничего долгого в кадре (> 2–3 мс):** воркеры (`src/world/terrain.worker.js`, чистые модули без THREE, детерминированно — `tests/unit/terrain-worker.test.js`) или по кусочку за кадр с бюджетом `performance.now()`; много объектов разом — по одному-нескольку за кадр, ближние первыми.
3. **Землю в кадре не делать:** вдали сначала `TerrainData.landMade(x, z)`, не `data.chunk()`.
4. **Шейдеры и звуки — на загрузке:** новый материал/модель — образец в `Game.prewarm`/`prewarmAsync` (список `zoo`), звуки синтезируются заранее. Свет: один общий на систему (`intensity = 0`, когда не нужен), не `PointLight` на объект и не `light.visible`.
5. **Мало вызовов отрисовки:** общие геометрии из кэша (ключи не дробные), слияние частей одного материала (`src/core/MergeGeometry.js`: `mergeParts`, `mergeInto`), много одинаковых неподвижных — `InstancedMesh`, ходящее — `src/core/FarShape.js` (скиннинг на видеокарте, части — кости); вдали позировать реже, вне кадра не позировать.
6. **Частицы** — из пула (`GlowPool` в `src/fx/Particles.js`), не создавать на каждую вспышку.
7. **Без мусора в горячем коде:** модульные `_v`-векторы и переиспользуемые массивы, `hypot` из `src/core/FastMath.js`, без `const [a, b] = ...` и копий `[...map.values()]`. Кто делает мусор — `node tools/flightbench.mjs --alloc`.
8. **Ничего не копится и вдали убирается:** `visible = false`/unload (`_unloadCaves`), `dispose()` своих геометрий, Map/Set чистить при удалении, списки с пределом (`src/core/CappedLog.js`), пулы и кэши с пределом.
9. **Перерисовывать только изменившееся** (миникарта, текстуры воды, тени); изменения мира — через воркер (`TerrainView._sendRebuild`).
10. **Сеть:** слать только изменившееся, маленькими сообщениями, большое — кусками. Поток камеры (SSE) — числа округлены (точек тысячи: JSON.parse в главном потоке), процессы на пути КАЖДОГО кадра камеры (кисти V5 на видеокарте) — не с пониженным приоритетом (наравне с нейросетью жителей они ждали её: «камера шлёт раз в 63–100 мс»).
11. **Замеры перед пушем (пороги только ужесточать):** `node tools/flightbench.mjs --check` (полёт, шейдеры в полёте), `creativebench.mjs --check` (старт Творческого), `soakbench.mjs --minutes 15 --check` (рост со временем), `spellbench.mjs --only <заклинание>`, `entrybench.mjs --check` (вход в мир), при необходимости `ultrabench.mjs`, `wakebench.mjs`.
12. **Вопросы себе:** что будет на слабой видеокарте? держится ли 60 FPS? что вырастет за 15 минут игры? сколько новых вызовов отрисовки и шейдеров?
