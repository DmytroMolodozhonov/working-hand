# Бенчмарк кистей (handbench)

Свой набор проверок кистей именно для нашей игры: игрок стоит далеко (в кадре видно тело до колен), поэтому
кисть занимает всего 25–60 пикселей; кулак, ладонь или тыльная сторона к камере, кисть направлена в камеру,
быстрые взмахи. По нему выбиралась версия кистей V5 (`hand_v5.py`). Итоги последнего запуска — в
[`RESULTS.md`](RESULTS.md).

## Как запустить

```bash
pip install mediapipe opencv-python numpy onnxruntime ai-edge-litert
python tools/handbench/fetch.py            # один раз: разметка + фото (~90 МБ, в .handbench/, не в git)
python tools/handbench/bench.py            # все проверки → tools/handbench/RESULTS.md (около часа на 4 ядрах)
python tools/handbench/bench.py --quick    # маленькая часть, пара минут
python tools/handbench/tune.py             # подбор чисел V5 только на части «dev»
python tools/handbench/load.py             # нагрузка всей программы камеры: V3 против V5
node tools/handbench/flight.mjs v3,v5      # полёт над новым миром: FPS игры и задержка кисти
node tools/handbench/pointbench.mjs --check   # куда указывает палочка V5: смещение, дрожь, задержка камера → экран, перелёт (синтетика, без камеры)
python tools/handbench/far.py ЗАПИСЬ.mp4 --hands [--backlight]   # дальний игрок: человек в 1,5×/2×/3× дальше, было → стало (приближение, свет)
```

RTMPose для сравнения: положите `rtmpose_hand.onnx` в `.handbench/models/` (или его скачает сама игра при
включённой V5 с видеокартой: `vendor/mediapipe/models/v5/rtmpose_m_hand5_256.onnx`, проверка SHA-256).

## Данные

* **COCO-WholeBody v1.0, val** (Jin и др., ECCV 2020) — кисти размечены людьми (21 точка). Файл разметки в
  формате openpifpaf, проверяется по SHA-256. Разметка — только для исследований: в игру она не входит.
* **Фото COCO val2017** — скачиваются по одному, только те, где есть хорошо видимая кисть ≥ 45 px.
* Выбираются 600 кистей (≥ 18 из 21 точки размечены, видны запястье и локоть). Части: «dev» — 3 кисти из каждых
  10 (на ней подбираются числа V5), «test» — остальные 7 из 10 (по ней отчёт).

## Как устроена проверка

1. **Маленькая кисть, как у нас.** Всё фото уменьшается так, чтобы кисть стала 24 / 32 / 48 / 64 px в кадре
   640×480 (и в 1.5 раза больше — в кадре 720p), человек в кадре, вокруг серое. Затем «как веб-камера»:
   лёгкое размытие оптики, шум матрицы, JPEG 80.
2. **Тело** находит MediaPipe Pose (модель full, как в игре); от него двухэтапные способы берут запястье.
   Если поза не нашла этого человека (толпа, обрезанное фото — в игре игрок один и целиком), запястье и локоть
   берутся из разметки с шумом 0.15 размера кисти.
3. **Метрики** (кисть, которую способ не нашёл, считается за 0):
   * «найдено» — доля кистей, найденных рядом с настоящей;
   * PCK@0.2 / PCK@0.1 — доля суставов ближе 0.2 / 0.1 размера кисти к настоящим;
   * ошибка — среднее расстояние суставов (в долях размера кисти, только у найденных);
   * «палочка» — угол направления кисти (запястье → костяшка среднего пальца: за ним идёт палочка в V4/V5)
     против настоящего; «< 15°» — доля кистей, где палочка смотрит почти точно;
   * отдельно: кулак / раскрытая / полусогнутая (по настоящим точкам), ладонью / тыльной стороной к камере,
     кисть направлена в камеру (укорочена);
   * **быстрый взмах** — кадр смазан на 0.45 размера кисти в случайную сторону;
   * **неподвижная кисть потоком** — 20 кадров одного фото с новым шумом камеры и дрожанием ±0.5 px:
     сколько кадров кисть есть, насколько дрожат точки и направление палочки — сразу и после фильтра игры
     (`HandFilter` из `src/input/TrackingGuard.js`, повторён в `common.py` с теми же числами);
   * **скорость** — мс на кадр и процессорное время (сумма по всем потокам) на этом компьютере.

## Сравниваемые способы (`methods.py`)

| способ | что это |
|---|---|
| `mp_full` | как сейчас в V3/V4: MediaPipe HandLandmarker по всему кадру (поиск ладони + суставы) |
| `mp_crop` | участок вокруг запястья из позы, увеличенный, и в нём весь HandLandmarker (с поиском ладони) |
| `rtmpose_hand` | RTMPose-m hand5 (OpenMMLab) на участке вокруг запястья, два взгляда; только 2D |
| `v5` | **V5 на процессоре**: сеть суставов MediaPipe прямо на повёрнутом участке от позы, второй взгляд по самой кисти, дальше слежение по её точкам |
| `v5_rtm` | **V5 с видеокартой**: точки — RTMPose, глубина и «кисть ли это» — сеть суставов MediaPipe на участке по этим точкам |

Важно для честности: RTMPose учился в том числе на COCO-WholeBody (другие фото, но та же манера разметки), поэтому
в этом наборе у него небольшое преимущество; MediaPipe этих фото не видел.

## Видео-бенчмарк: настоящая запись игрока (`video.py`)

Фото COCO не показывают главного — что происходит **во времени**: кисть пропадает на кадр-другой, когда сжимается
в кулак или смазана быстрым взмахом, и игра видит «рука исчезла — появилась». Поэтому есть второй бенчмарк — по видео
с камеры игрока (автор записал 42 с: кулак с палочкой, раскрытая кисть, «руки вверх», взмахи, подход к камере).
Само видео в репозиторий не кладётся (это запись человека): его путь передаётся программе, на диск пишутся только числа
(`.handbench/video/<имя>/`, не в git).

```bash
python tools/handbench/video_ref.py ВИДЕО.mp4                 # эталон, один раз (~10 мин на 4 ядрах)
python tools/handbench/video.py ВИДЕО.mp4 --method v5,v5prev   # способы — как их видит игра (1280×720, 30 кадров/с)
python tools/handbench/video_report.py                         # таблица
python tools/handbench/video.py ВИДЕО.mp4 --method "v5:PRESENCE=0.2,v5:HOLD=0.3"   # те же V5 с другими числами
```

* **Тело** — как в `pose_native.py`: PoseLandmarker (full) по копии 640 px, режим VIDEO, со стражем `pose_guard.py`
  (`--pose plain` — без стража, как было).
* **Эталон** (`video_ref.py`): тело — по каждому кадру отдельно (heavy, IMAGE, 960 px); кисть — сеть суставов MediaPipe
  на 12+ квадратах (от тела 4 размера × 3 поворота, от точек кисти в соседних кадрах — вперёд и назад по времени),
  лучший; RTMPose смотрит ту же кисть — «уверенный» эталон там, где они согласны.
* **Отчёт**: «есть в игре» — кисть дошла до игры (счёт ≥ 0,5, как берёт `assignHands`); **«верно»** — дошла и стоит
  там, где эталон (запястье и средняя костяшка ближе 0,5 размера кисти); «мимо» — дошла, но не там; провалы — сколько
  кадров подряд кисти нет; «кулак» — «верно» только на сжатых кистях. `v5prev` — V5 до этой работы
  (`.handbench/hand_v5_prev.py` = `git show <коммит>:hand_v5.py`).

### Итоги (видео автора, 24.10.2026: 1264 кадра, кисть в кадре 2207 раз, эталон уверен в 82 %)

| способ | есть в игре | **верно** | мимо | удержана | провалов ≥ 5 кадров | самый долгий провал | кулак: верно |
|---|---|---|---|---|---|---|---|
| V5 как была в игре (без стража тела) | 65,2 % | **53,8 %** | 11,5 % | — | 58 | 64 кадра (2,1 с) | 56 % |
| V5 как была + страж тела | 74,5 % | **73,2 %** | 1,3 % | — | 55 | 16 | 77 % |
| MediaPipe целиком (V3) + страж тела | 76,3 % | **75,3 %** | 1,0 % | — | 36 | 29 | 76 % |
| V5 на процессоре | 99,2 % | 95,7 % | 3,5 % | 9,6 % | 0 | 4 | 92 % |
| **V5 на видеокарте** (`v5gpu`: квадраты не меньше плеч, перебор поворотов) | **99,3 %** | **95,5 %** | 3,9 % | 6,3 % | 0 | 4 | **94 %** |
| V5 с RTMPose (видеокарта), без оптического потока | 99,6 % | 94,2 % | 5,4 % | 9,1 % | 1 | 5 | 92 % |

Что нашлось и что сделано:

1. **Тело «залипало» на 16 с** (в начале записи игрок подошёл к камере и отошёл): плечи выше носа в 92 % кадров,
   запястья на стене — и V5 искала кисти не там. Тот же кадр сам по себе — верен в 100 %. → `pose_guard.py`: тело
   проверяется каждый кадр (`sane`) и раз в 20 кадров сверяется со свежим взглядом; не тело — свежий взгляд и замена
   следящей сети на запасную (сделана заранее, в фоне; не чаще раза в 15 кадров); странная, но настоящая поза (наклонился к
   камере), которую подтвердил свежий взгляд, принимается. Тело «не там»: 41 % кадров → 2,5 % (первые секунды у самой камеры);
   правильные позы бракуются в 1,9 % (руки в стороны — до 3,7 ширины плеч, предел `ARM_MAX` 5), залипшие ловятся в 95 %.
2. **Игра выбрасывала кисти V5 с уверенностью 0,3–0,5** (`assignHands` берёт с 0,5, а V5 давала свою «уверенность
   сети»). → V5 сама решает, кисть ли это, и отдаёт счёт ≥ 0,5; сырая уверенность — в `presence`.
3. **Сжатая, смазанная или повёрнутая кисть** — сеть сомневается (0,05–0,3) несколько кадров, точки при этом верны.
   → сомнительная кисть берётся, если она там, куда шла, своего размера и с той же ладонью (`_consistent`, `_palm_ok`),
   и не дальше размера кисти от запястья тела (`WRIST_FAR`: квадрат больше не уезжает на предплечье).
4. **Потерянная кисть искалась через кадр и только в квадрате от тела** (рука к камере — больше квадрата). → пока тело
   видит запястье — каждый кадр, и ещё квадрат в 1,6 раза больше (`WIDE`).
5. **Сильный смаз при взмахе** не видит ни одна сеть (RTMPose тоже). → кисть **удерживается** до 0,5 с (`HOLD`), пока
   тело видит запястье, и движется вместе с картинкой вокруг неё (оптический поток Лукаса–Канаде, ~1 мс); в поток
   идёт и следующий квадрат слежения (`TRACK_FLOW`: +1,4 % «верно», кулак +3 %). Удержанная кисть помечена `held`.

6. **Палочка прямо на цель (в камеру)** — предплечье и ладонь укорачиваются, квадрат от тела и квадрат слежения
   становились меньше самого кулака; у такой кисти нет ясного «верха» (сеть хочет пальцы вверх: при неверном повороте
   — 0, при верном — 0,7–0,9). → квадраты не меньше 0,8 / 0,6 ширины плеч (`POSE_MIN`, `TRACK_MIN`: плечи не
   укорачиваются); на видеокарте потерянная кисть просматривается в 12 поворотах и 2 размерах одним вызовом (`SWEEP`);
   неподвижная потерянная кисть (прицел) держится до 2 с (`HOLD_STILL`). Правая рука «удержана» 89 кадров вместо 148,
   в отрезке «палочка вперёд» (33–37 с) — 14 вместо 26.

Числа устойчивы (перебор `PRESENCE` 0,2–0,4, `PALM_TOL` 0,25–0,5, `WIDE` 1,6–2, `HOLD` 0,3–0,8, `WRIST_FAR` 0,7–1,4:
везде 95,2–95,9 %); разница в ±0,4 % — шум слежения (крошечное отличие кадра расходится дальше).
Цена (этот контейнер, 4 ядра, без видеокарты): обе кисти параллельно — 20 мс на кадр в среднем против 13 у прежней V5
(больше взглядов, пока кисть ищется); здесь один взгляд сети кисти стоит ~11 мс, на обычном компьютере — 2–4 мс.
